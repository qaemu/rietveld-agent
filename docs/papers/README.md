# docs/papers — the rietveld-agent paper series

Three working papers explain **how the software works**, **why it is
scientifically valid**, and **how to run it on any agent runtime**. All
papers are markdown (GitHub-native); every number they cite is generated
from the repository with `make` and the spike-16 harness.

## The series

| paper | question | abstract |
|---|---|---|
| [P-1 — protocol](paper1_protocol.md) | How does the software work? | A deterministic, budget-bounded Rietveld QPA protocol for the four NIST SRM 2686a reference patterns: COD-pinned md5-recorded structure set, staged GSAS-II refinement ladder, Hill–Howard normalization, canonical content-hash reproducibility. All six refinements converge (wR 9.8–27.1%). |
| [P-2 — validation](paper2_validation.md) | Why is it scientifically valid? | Three-pronged proof: (A) bit-identical reproduction across independent runs (canonical md5 `f43d8be2…`), (B) known-answer recovery of all 24 injected phase rows within ±1.5/±1.0 wt% on Poisson-corrupted synthetic patterns, (C) honest gate scoring (operational 5/6, publication 0/6, residual gap attributed to microabsorption). |
| [P-3 — deployment](paper3_deployment.md) | How do I run it? | Installation and verification of the engine from OpenCode, Claude Code, and Codex on macOS/Linux/Windows, plus the five governance invariants that make agent-driven scientific work safe. Full reference: [docs/installation.md](../installation.md). |

## Construction

The series is written following the fifteen-step scientific-writing
framework of Drake & Han (2025), *How to write a scientific paper in
fifteen steps*, PLoS Comput. Biol. 21(9):e1013505,
doi:10.1371/journal.pcbi.1013505 (PMC12459795): thesis-first abstract,
story, methods and rationale, CARS introduction, findings and
problem–response pairs, and paragraph/figure planning. The writing
methodology is cited in each paper.

## Reproduce

The papers are static documents; their numbers are generated by:

```bash
make report    # protocol refinements (~45 min)
python3 benchmarks/spikes/spike_16_validate.py   # validation evidence (~32 min)
```
